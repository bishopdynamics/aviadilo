# Aviadilo 0.1.0-dev.2 — candidate release notes

Development prerelease under acceptance. An explicit `v0.1.0-dev.2` tag triggers the checked build and publishes `aviadilo.zip`; an ordinary source push does not publish a release.

The Aviadilo card combines aircraft, radar, wind and existing household `device_tracker` entities in one map. The companion integration shares collection, provider pacing and bounded caches across viewers. One HACS Integration ZIP includes the backend and matching compiled card.

- Aircraft markers, selectable list and details, with distance/altitude/age filters and local selection trails.
- RainViewer, NOAA MRMS and KSOX radar history, playback, timestamps, coverage messages and source legends.
- DWD ICON-global wind arrows, barbs and bounded local particles, with reduced-motion support.
- Household radius filtering before rendering or fitting, manual view control and recentering.
- Full graphical card editor and graphical shared integration settings. Picker/editor previews use synthetic data.
- Automatic versioned card loading, reconnect/reload recovery, and cleanup when cards are hidden or removed.

Compatibility baseline: Home Assistant 2026.9.1. Local browser checks use Chromium 151.0.7922.34 and 153.0.8010.12 on Linux. The user's physical tablet remains untested.

Package: `aviadilo.zip`; integration-root layout, 23 runtime files plus the MIT `LICENSE`. SHA256: `90c74ee5333e26331c5fd1b396cac46ae904854ff0d32b4389e8d7f8193b8463`. Runtime files are byte-identical to the candidate tested in the 20-minute HA run; the license is the only added archive entry.

Local CI gates passed 123 frontend tests, 258 backend tests and 11 offline Chromium scenarios, along with lint/types, builds and release checks. Official pinned hassfest found zero invalid integrations. Local HA upgrade retained saved settings; the actual HACS 2.0.5 installer passed install/upgrade with mocked GitHub metadata and HTTP transport. See [the development guide](../development.md) for scope and evidence.

HACS custom-repository delivery is required; default-catalogue submission is optional. Repository license, description and topics checks are tracked separately from the release asset build. The current workflow publishes a development prerelease only after an explicit version-tag push, successful CI checks and exact package/tag version validation. Real household installation and physical tablet acceptance remain to be confirmed.

A 20-minute run of two Chromium clients against real HA with synthetic providers passed with zero JavaScript/tile errors, stable DOM counts and bounded radar/wind resources. This does not replace physical tablet or overnight acceptance.

The map is intended for household dashboard awareness. Each source has its own data and refresh times; radar playback does not rewind aircraft or household locations. Source coverage and availability vary.
